# TEE FTL V3 implementation plan

Restore point: `9d719b9333b949bdfb3850c8ff2af4ec9b766ac2`

V3 retains the complete V1/V2 policy. Its new surface is internal/test-only;
custom NVMe admin command transport is deferred to V4.

## V3-STORAGE — hidden metadata storage

- Version/module: V3 `storage`.
- Behavior: model the reserved tail LBA region as durable hidden storage for
  passive metadata, protected bitmap, and HMAC group metadata. Active metadata,
  pending bits, and working HMAC state remain RAM-only. Normal NVMe I/O remains
  limited to the visible namespace.
- Expected files: `tee/tee-v3-storage.[ch]`, storage tests, Makefile.
- Tests: classification, capacity/layout bounds, passive/bitmap/group snapshot.
- Commands: focused gcc test target, then full `make test`.
- Commits: `test(v3-storage)` followed by `feat(v3-storage)`.
- Dependencies: clean passing V2 at the restore point.
- Stop: any requirement for reboot recovery, V4 transactions/writeback, or
  exposing hidden LBAs through normal I/O.

## V3-READ — protected read metadata queries

- Version/module: V3 `read`.
- Behavior: internal/test READ_SUMMARY, READ_LOCATIONS, and READ_HMAC_GROUPS.
  Summary reports all locked counts, item sizes, and page counts; location pages
  contain only logical segment addresses; group pages contain start index,
  count, and expected HMAC. Normal data reads remain unrestricted.
- Expected files: `tee/tee-v3-read.[ch]`, read tests, Makefile.
- Tests: normal-read rule, not-found/bounds, exact summary fields, and
  pagination without extra segment indexes.
- Commands: focused gcc test target, then full `make test`.
- Commits: `test(v3-read)` followed by `feat(v3-read)`.
- Dependencies: V3-STORAGE.
- Stop: any need for V4 NVMe admin request/response formats.

## V3-PROOF — one-bit proof and pending timeout

- Version/module: V3 `proof-timeout`.
- Behavior: internal/test ONE_BIT_PROOF states for passive done, active missing,
  active complete/about-to-persist, previous persistence error, and not found.
  Default timeout is 1000 operations. Active metadata touch, HMAC-group touch,
  segment arrival, and ONE_BIT_PROOF refresh the deadline. Expiry clears only
  RAM active/pending state.
- Expected files: `tee/tee-v3-proof.[ch]`, proof/timeout tests, V3 policy glue,
  Makefile.
- Tests: every proof state, missing-index pagination, touch refresh, expiry,
  and preservation of passive/protected persisted state.
- Commands: focused gcc test target, then full `make test`.
- Commits: `test(v3-proof-timeout)` followed by `feat(v3-proof-timeout)`.
- Dependencies: V3-STORAGE and V3-READ.
- Stop: delete/status semantics beyond existing V1/V2 or V5 rollback behavior.

## V3-FLOW — version integration and build

- Version/module: V3 `flow`.
- Behavior: integrate the V3 storage/read/proof/timeout context with the complete
  V1/V2 behavior and build a `tee-ftl-v3-policy.so` prototype.
- Expected files: `tee-ftl-v3-policy.[ch]`, integration test, Makefile, this doc.
- Tests: one flow proving V1 write guards, V2 promotion/HMAC, V3 persistence
  snapshot/read queries/proof/timeout, plus the complete prior-version suite.
- Commands: focused V3 flow target, `make test`, and gcc policy build.
- Commits: `test(v3)` followed by `feat(v3)` and a separate `build(policy)` if
  the build hook is not inseparable.
- Dependencies: all V3 module tasks.
- Stop: real FEMU execution, V4 admin transport, or V5 delete/status behavior.
