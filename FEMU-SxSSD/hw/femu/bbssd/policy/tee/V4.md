# TEE FTL V4 implementation plan

Restore point: `feabc94c49e866de694d1f6f7251b73844b52a12`

V4 retains V1, V2, and V3 behavior. It adds authenticated custom NVMe admin
transport, paginated response state, and a prototype metadata writeback
transaction module.

Implementation status: complete for software/unit-test prototype. Real FEMU
execution is still user-gated. Reboot recovery remains deferred.

## V4-ADMIN-FORMAT — verified admin command format

Status: complete.

- Behavior: fixed little-endian request/response headers, 4096-byte default
  admin buffer, vendor-range opcodes, and a 32-byte request MAC.
- MAC rule: HMAC-SHA256 with the fixed V2 prototype key over all request header
  fields before `request_mac` plus the declared payload bytes.
- Commands: `READ_SUMMARY`, `READ_LOCATIONS`, `READ_HMAC_GROUPS`,
  `ONE_BIT_PROOF`, and `SYNC_METADATA`.
- Files: `tee/tee-v4-admin-format.[ch]`.
- Test: `test_tee_v4_admin_format`.

## V4-ADMIN-RESPONSE — submit/fetch/continue pagination

Status: complete.

- Behavior: one pending response per policy prototype. `SUBMIT` prepares a
  response, `FETCH` materializes page 0, and `CONTINUE` materializes later
  pages by `request_id` and `page_index`.
- Files: `tee/tee-v4-admin-response.[ch]`.
- Test: `test_tee_v4_admin_response`.

## V4-WRITEBACK — cache writeback and transaction records

Status: complete as a reusable module.

- Behavior: chunk commit flushes immediately. Relocation metadata is batched
  and flushes on batch limit, timeout, cache pressure/SYNC caller path, or
  explicit sync.
- Transaction records carry type, transaction id, state, file/chunk id,
  segment index, old location, and new location.
- Ordering rule represented by each relocation record: persist new protected
  location and new passive location before old protected location is unmarked.
- Files: `tee/tee-v4-writeback.[ch]`.
- Test: `test_tee_v4_writeback`.
- Boundary: the existing V2 relocation primitive still performs its RAM
  mark-new/unmark-old sequence directly. V4 records the durable transaction
  model, but full relocation crash recovery/replay is deferred.

## V4-ADMIN — FEMU policy integration

Status: complete.

- Behavior: `tee-ftl-v4-policy.so` layers on the V3 policy state, registers
  admin hooks for `SUBMIT`, `FETCH`, and `CONTINUE`, verifies request MACs, and
  exposes V3 protected-read metadata through custom admin commands.
- Files: `tee/tee-v4-admin.[ch]`, `tee-ftl-v4-policy.[ch]`, Makefile.
- Test: `test_tee_v4_admin`.

## Deferred work

- V5: expanded error/status behavior, delete command with integrity check, and
  rollback reporting through one-bit-proof.
- V6/later: key-sharing integration, attestation, reboot recovery, and
  persistent transaction replay after FEMU restart.
