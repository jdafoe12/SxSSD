# SxSSD: A Secure and eXtensible Software-defined Solid State Drive

## 1. Organization

The `FEMU/` folder is the baseline FEMU tree used for comparison. We have modified it only to have a backend that writes data to the location corresponding the the physical page address generated by the FTL.

The `FEMU-SxSSD/` folder is the SxSSD implementation. The main SxSSD-specific code is under `FEMU-SxSSD/hw/femu/bbssd`.

The code of our implemented policies can be found in the policy folder. The scripts for accessing the meta-interface and installing the different policies is in the scripts folder.


The virtual machine image for running the experiments can be found at https://drive.proton.me/urls/GMJXK9CCV8#o8yaVm1tBDqA. 

(the VM login is `femu` and the password is `femu`)

Workloads and generated results are intentionally not bundled in this compressed artifact. Reviewers should use the provided VM for workloads and regenerate all results locally.

## 4. Host Setup

From the artifact root, source the helper script:

```bash
cd /path/to/SxSSD
source ./reviewer_env.sh
```

If you need non-default paths, export overrides first and then source the script:

```bash
export FEMU_IMAGE_DIR=/data/vm-images
export FEMU_OS_IMAGE=/data/vm-images/u20s.qcow2
export FLASHGUARD_RESULTS=/path/to/flashguard/results
cd /path/to/SxSSD
source ./reviewer_env.sh
```

## 5. Build Both Projects

The build should take place on a system with Ubuntu 20.04 LTS or newer.

If your host OS is different, you may use distrobox or another containerization method.

Build baseline FEMU:

```bash
cd "$ARTIFACT_ROOT/FEMU"
mkdir -p build-femu
cd build-femu
cp ../femu-scripts/femu-copy-scripts.sh .
./femu-copy-scripts.sh .
./femu-compile.sh
```

Build SxSSD:

```bash
cd "$ARTIFACT_ROOT/FEMU-SxSSD"
mkdir -p build-femu
cd build-femu
cp ../femu-scripts/femu-copy-scripts.sh .
./femu-copy-scripts.sh .
./femu-compile.sh
```

For more information, check the build instructions in the FEMU or FEMU-SxSSD README.md files.

## 6. Result Directory Mount Inside The VM

Whenever the VM is running and you want results copied back to the host, mount the host-shared results directory inside the guest:

```bash
sudo mkdir -p /mnt/femu-host-results
sudo mount -t 9p -o trans=virtio,version=9p2000.L femu_host_results /mnt/femu-host-results
```

## 7. Collecting workload results.

This is the main workload comparison between baseline FEMU, SxSSD-Block, and SxSSD-FlashGuard.

Use this workload list:

```text
systor_11
systor_06
systor_05
msr_prxy_0
msr_prn_0
msr_mds_0
fiu_web_02
fiu_mail_03
fiu_homes_02
alibaba_08
alibaba_01
```

Guidelines:

- restart the VM between workload units
- do not run policy setup on baseline `FEMU/`
- for `FEMU-SxSSD/`, install the correct policy after boot and before running the workload

### 7.1 Baseline FEMU Procedure

For each workload unit in the list above, repeat the following sequence.

Host terminal A:

```bash
cd "$ARTIFACT_ROOT/FEMU/build-femu"
../femu-scripts/set_cpu_perf_mode.sh
FEMU_IMAGE_DIR="$FEMU_IMAGE_DIR" \
FEMU_OS_IMAGE="$FEMU_OS_IMAGE" \
FEMU_HOST_RESULTS_DIR="$BASELINE_RESULTS" \
./run-blackbox.sh
```

Host terminal B, after the VM boots:

```bash
cd "$ARTIFACT_ROOT/FEMU/build-femu"
./pin.sh
```

Inside the VM:

```bash
sudo mkdir -p /mnt/femu-host-results
sudo mount -t 9p -o trans=virtio,version=9p2000.L femu_host_results /mnt/femu-host-results
cd ~/workload-eval/workload_sets
```

Run exactly one workload unit:

```bash
sudo python3 scripts/run_workload_set.py core_writeheavy block --target /dev/nvme0n1 --nvme-dev /dev/nvme0 --unit "<WORKLOAD_UNIT>" --measure long --cap 10 --scaled --ssd-size-mb 12288 --replay-time-scale 100 --repetition-id 0 --build-label FEMU --log-avg-msec 100
```

Example:

```bash
sudo python3 scripts/run_workload_set.py core_writeheavy block --target /dev/nvme0n1 --nvme-dev /dev/nvme0 --unit "systor_11" --measure long --cap 10 --scaled --ssd-size-mb 12288 --replay-time-scale 100 --repetition-id 0 --build-label FEMU --log-avg-msec 100
```

After the workload completes, shut down the guest:

```bash
sudo poweroff
```

Repeat the same sequence for the next workload unit.

Baseline results are written under:

```bash
$BASELINE_RESULTS
```

## 8. Max-I/O Evaluation

The scripts for this are in

```text
/home/femu/scripts/max_io_collection
```

### 8.1 Baseline FEMU Max-I/O

Launch baseline FEMU as in Section 7.1. Inside the VM, mount `/mnt/femu-host-results`.

Reboot the VM between each test: First, run ./01_prepare_read_region.sh then run the other workload.
```bash
cd /home/femu/scripts/max_io_collection
sudo env SYSTEM_LABEL=FEMU DEVICE=/dev/nvme0n1 ./01_prepare_read_region.sh
sudo env SYSTEM_LABEL=FEMU DEVICE=/dev/nvme0n1 ./02_run_max_read.sh
sudo env SYSTEM_LABEL=FEMU DEVICE=/dev/nvme0n1 ./03_run_max_write.sh
sudo env SYSTEM_LABEL=FEMU DEVICE=/dev/nvme0n1 ./04_run_seq_read.sh
sudo env SYSTEM_LABEL=FEMU DEVICE=/dev/nvme0n1 ./05_run_seq_write.sh
```

### 8.2 SxSSD Max-I/O

Launch SxSSD as in Section 7.2. Inside the VM, mount `/mnt/femu-host-results`, install the needed policy if required by your max-I/O workflow, then continue as before:

```bash
cd /home/femu/scripts/max_io_collection
sudo env SYSTEM_LABEL=SxSSD DEVICE=/dev/nvme0n1 ./01_prepare_read_region.sh
sudo env SYSTEM_LABEL=SxSSD DEVICE=/dev/nvme0n1 ./02_run_max_read.sh
sudo env SYSTEM_LABEL=SxSSD DEVICE=/dev/nvme0n1 ./03_run_max_write.sh
sudo env SYSTEM_LABEL=SxSSD DEVICE=/dev/nvme0n1 ./04_run_seq_read.sh
sudo env SYSTEM_LABEL=SxSSD DEVICE=/dev/nvme0n1 ./05_run_seq_write.sh
```

Max-I/O outputs are written under:

```bash
$BASELINE_RESULTS/max_io/json
$SXSSD_RESULTS/max_io/json
```

```bash

cd "$ARTIFACT_ROOT/FEMU-SxSSD/build-femu"

FEMU_META_DEVICE_TIMING_CSV="$FEMU_META_DEVICE_TIMING_CSV" \

```

Host terminal B, after the VM boots:

```bash
cd "$ARTIFACT_ROOT/FEMU-SxSSD/build-femu"
```

Inside the VM:

```bash
sudo mkdir -p /mnt/femu-host-results
```
